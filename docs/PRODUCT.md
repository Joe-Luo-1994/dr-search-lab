# DR 討論介面的產品脈絡

2026-11-10（Asia/Taipei）。目的：讓內部 DevOps 與方案準備者共同形成有條件的 v1，再找 FDE 與一個核心 consumer owner 挑戰。不是工具選美、正式簽核或以測試數量取代採用。

## 對象與他們進來要做的事

- 核心 DevOps 熟悉現有 Infra；需要看見沿用 Web 的可行路徑、額外工作與資源限制，並修正架構底圖。
- Reviewer 可能不熟技術；需要理解哪些營運任務能繼續、未解風險及需要協調的合作。
- 核心 consumer 需要確認接入契約、身份、版本與失敗行為，並估算自己要付出的成本。
- PM 代表產品 user；已確認 readonly／下載／搜尋方向，要補代表性任務與可接受門檻。
- FDE 帶來跨系統能力與方向資訊；需要一個可挑戰的初稿，不要求替未釐清需求背書。

## 一次會議的成果

修正現況、看一個重要任務、比較責任、留下暫定方向／未知／owner／檢查點。正式批准與對口確認另行追蹤；介面不預填同意，不用綠燈或進度百分比暗示完成。

## 約束與已知事實

現行DR已有Next.js＋MinIO＋Cronjob＋內部ReBAC，缺搜尋／consumer API／完整授權。Lab是合成資料／mock，不是實際DR。先在公司Linux主機／容器Demo；已有內部Harbor、可能部分API（使用者回報），版本、scope、映像、CA、npm來源尚未查核。雲端工具目前無內網連線。任何真實資料、憑證與詳細內部inventory留在公司環境。

頁面不引入CDN、遠端字型、圖片服務、analytics或新UI套件；討論筆記只在頁面記憶體，明確下載到使用者裝置，不建儲存API。僅去敏討論摘要可輸入。

## 仍待使用者驗收

能否在一分鐘理解會議目的；能否指出一個自己關切的缺口；是否容易切換情境與找到限制；是否感覺可以提出不同意／不知道；會後是否取得可執行下一步。雲端browser checks不能代替這些人的感受與理解。
