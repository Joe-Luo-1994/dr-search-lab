## 1. 要作的決定

A完整異地方案是使用者確認的可行基準；B保留ES、替換周邊依賴；C Next＋本地SQLite＋異地MinIO＋ReBAC。研究檢查B/C能否以可接受的功能差異降低整體負擔，尤其每新增一處備援。沒有節省證據也是有效結論；不預選C。

依序取得：成本／責任地圖 → 小型必要任務與差異 → 必要維運操作 → 有選型價值的容量比較。最多三張技術實驗卡E1–E3，依前輪結果決定是否進下一輪；E0是資料盤點，不是另一次壓測，也不先承諾三輪全跑。

## 2. 最小工作順序與卡片

### E0：先判斷省在哪裡（盤點，V8）

- 問題：A能沿用多少？B/C少掉的資源是否換成更多程式與操作責任？
- 輸入：既有部署／資料流／實驗／runbook；公司部署自動化尚無輸入則明列未知。
- 產出：A/B/C同一張能力及責任表，分一次性改造、共用build／維護、每站服務與同步、每Pod快取、consumer修改、跨站演練。各格標實測／程式證據／估計／未知，附來源及負責方；不以程式行數當維運工時。
- 成本先列資源與工時範圍，不先虛構單價；站點N=1/2/4為示例，期間1年／3年為敏感度假設，不是已確認部署或預算。共同附件成本仍列總額，但避免冒充C專屬節省。
- 必填選型連結：哪項成本可能改變A/B/C選擇 → 現有範圍／未知 → 下一卡測哪個量 → 何種結果保留／停止分支。例如「省掉各站ES是否抵得過C的維護」：E1量必要任務修補責任、E2量操作、E3量資源；沒有ES基準或工時估計時只能排除不適合者，不能證明淨節省。若即使採最有利假設仍無收益，停止該分支；範圍重疊則報不確定，不硬排名。
- 加一份情境→舊證據→本輪改變接縫→需否重測映射：MR1缺件／hash／失敗保舊與MR2依賴失聯等先引用；相同實作與契約不完整重跑。新Next／Tags／PDF adapter影響到的邊界才選代表案例，防止E2自動展開全矩陣。
- 退出條件：有一個可能翻轉選型的主要成本假說，便可進E1；無資料無法比較則保留分支，允許有獨立價值的E1，但不得宣布B/C較省。已有證據顯示替代方案不值得，則停止該分支。
- 投入上限建議：盤點agent 45分鐘；主agent整合30分鐘。到點交付未知與缺口，不延伸成全公司資產調查。

### E1：必要搜尋＋一條完整任務鏈（V1/V2；V6底線）

- 決定：C是否值得繼續；B能否作保留ES的可行備案；替換周邊的成本有多大。
- 對照：既有B的ES-reference與C使用同一小型合成來源、API契約、可信身份集合及抽取文字；不把ES輸出當標準答案，也不把B冒稱原公司完整方案A。A契約與運行成本另列未知。
- 優先重用已有fixture／builder／Next／MinIO及editor接縫，新增獨立小fixture補Tags與PDF分支。不得覆寫凍結資料或重建百萬資料來解小型品質問題。
- 案例草案上限24張：12必要正向（中文短／長詞、英文、多詞明定AND、中英混合、技術碼、title、正文、PDF-only、Space、Tags AND、consumer整鏈，容許一題覆蓋多類）；8負向／錯誤（僅一tag、正文假tag、跨Space、無權身份、ReBAC unknown、錯page/media關係、真正無結果、服務錯誤）；4快照時效診斷（移頁、Role撤除、移除media、同步失敗）。覆蓋完整可合併刪題，不湊數；精確文件與查詢清單在執行卡固定後才能跑。至少一組查詢要有超過10個可見候選干擾頁；AND／Tags／PDF-only明列近似但應排除頁，避免Top10自然全裝進去的假成功。
- 獨立oracle：非實作者依來源語意列必要pageIds／禁止pageIds／附件hash及各輸出欄期望；涵蓋title／metadata、total、snippet、正文、附件bytes及錯誤訊息。實作者不得由當次引擎輸出回填。相同詞命中集合及排名不要求全等，但每題契約與排除條件必須成立。
- 研究門檻：凍結的必要任務全完成，搜尋第一頁10筆內含預期可辨認頁，指定pageId內容與必要附件正確；負向符合固定契約，unknown不ALLOW，錯誤不偽裝無結果。drift案例分開列「合成政策期望」「目前來源關係」「實際交付及暴露持續時間」，不把符合快照政策呈現為目前權限安全通過。freeze時固定metadata／membership版本、Role查詢時間及資料過舊政策；daily／4h不是同步失敗或來源失效時的age上限，不替owner接受風險。
- 每個搜尋／普通正文請求5秒為本輪有界研究期限，記超時為失敗；瀏覽器完整任務／PDF下載期限須按實際fixture大小在執行卡補定，未填不得執行。數值非正式SLO，舊2秒／5秒實驗結果不追溯改判。Web highlight可加分；synthetic consumer契約明寫是否依賴它，不能類推正式consumer。
- 產出：逐題B/C結果＋UI操作證據＋consumer回應差異＋provider新增責任。不聲稱新實作既有editor；如果缺可用editor，標明替代render與未驗接縫，不冒充完成既有產品整合。
- 投入上限建議：實作者120分鐘準備；一次凍結正式執行，必要時只允許一個有根據的修補分支。修補先改卡／版本，保存原失敗，不反覆調參到綠。超時留下可試用切片及未完成，不趕工改門檻。
- 分支：必要任務失敗且修補開始涉及持續詞典／語意仿真，優先評B/A；C與B都通過則進操作比較；共用接縫失敗先解共用問題，不歸因引擎。

### E2：更新與接手是否真的省事（V3/V8；V5/V6底線）

## 3. 分派：最多三個角色同時工作，不把每個步驟都變成agent

| 角色 | 責任與交付 | 模型／上下文策略 |
|---|---|---|
| 主agent／實驗負責人 | 選下一個決策、凍結卡片、整合、唯一正式runner、保全證據、向使用者提出真正取捨 | 延用主模型；不委外最終結論 |
| 盤點agent（按需） | 讀限定文件，回傳來源行號、已知／未知、可重用入口；不設計新架構、不跑負載 | 可用較便宜模型；短上下文＋精確路徑，主agent抽查關鍵引用 |
| 實作者（一輪一位） | 一張卡的一個程式／fixture範圍；小型自測與成本紀錄；不得擅改oracle／門檻 | 一般coding模型；遇跨服務、版本或權限推理失敗再升級，不先派多引擎實作者 |
| 獨立reviewer（必要關卡） | 挑戰假說／反例／比較公平性，審執行卡與diff，事後抽查原始證據、結果與成本，不只讀摘要 | 能處理證據與架構推理的模型；先沿用可用模型，不為省token降審查品質。非實作者，不自改受審程式 |

角色是按階段使用，不同時開四個agent。E0可盤點與review草案並行；E1/E2實作期間reviewer可獨立寫oracle／反例；量測全部串行，禁止兩組壓測互相搶資源。簡單引用、hash與摘要交腳本，不另外開agent。

本版不綁特定模型品牌或假設價差；實際派工記錄請求model／effort、可得開始／結束時間、tool calls、重工；token／價格拿不到填未知。過去Luna盤點、Sol實作／review的試行只提供可借鑑分工，沒有證明更便宜。每個子任務只帶目的、文件入口、寫入範圍、禁改項、退出條件與回報格式；不複製整段對話。上列分鐘數都是停止重新評估的投入上限建議，不是承諾完工時間；不因時間到而降低證據標準。

## 4. Reviewer兩道關卡與停止規則

1. **執行前**：本實驗會改變哪個決定？舊證據是否已足夠？oracle是否獨立？A/B/C是否同承諾？必要／加分／診斷是否分清？硬資源與時間限制是否可執行？能否再減一個變因？輸出可執行／需修正／無價值先停，附具體阻擋理由。
2. **執行後**：核對原始資料、失敗與分母、配置／來源hash、被排除樣本與量測干擾；核對功能收益是否轉嫁provider／consumer／Infra成本。輸出有限通過／失敗／證據不足＋主張邊界＋下一個最值得做或停止。

每張卡預設一次完整review與一次針對修正的複核；還有實質阻擋則停止執行／縮範圍，不能因review預算到期跳過。reviewer不可用時標未獨立審核，主agent自查不能代稱review通過。review不是需求owner批准。

完整執行卡必填：ID／V-ID／決策、來源與程式hash、oracle版本、精確case、API與授權政策、資源CPU/RAM/磁碟及可用容量護欄、時限與watchdog、seed／順序／冷暖cache、成功／失敗標準、輸出與保全位置、清理範圍、停止與重跑條件、成本紀錄。缺欄先補，不把本計畫直接當可執行腳本。

需找使用者討論：必要需求得降級、consumer要額外改造、快照風險需正式接受、成本假說翻轉而需改方案。可自行處理：測試bug、資料引用、同契約小修與隔離環境。任何門檻改動另版、保留原失敗，不能實驗中途救分。

## 5. 每輪給使用者的結果

先一頁：使用者任務能否完成 → 可見差異／限制 → 架構新增責任 → 共用／每站成本 → 本輪改變哪個決定。可展開的case與原始證據另附，不用測試數或合成漂亮數字代替結論。

本次設計交付只證明實驗可被審查；是否滿足正式需求、真實維運是否較低與人類可用性都仍待驗。下一步先E0；E1可與公司資料補充並行，不要求等正式未知全數消失。
