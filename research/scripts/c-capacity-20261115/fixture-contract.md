# Capacity fixture contract

`node fixture.mjs NEW_OUTDIR COUNT`: refuses existing output; COUNT 10..100000 (10k instrumentation smoke, 100k formal plan). No services started. Outputs `v1/search.sqlite`, `v2/search.sqlite`, each `manifest.json` and `objects/`, plus root `oracle.json` and `build-report.json`. Node 22.18+ with `node:sqlite`.

Each SQLite file has `metadata(snapshotId)` exactly `v1`/`v2`; `pages(pageId,spaceId,title,content,bodyKey,bodyBytes,bodySha,mediaId)`; `page_tags(pageId,tagId)`; `media(mediaId,key,bytes,sha256,mimeType)`; FTS5 `search_index(title,content)` rowid joins `pages.rowid`. Raw text is in pages.content; normalized text is in FTS. Normalize Han runs using `Intl.Segmenter('zh-Hant',{granularity:'word'})`, join word segments with spaces, collapse whitespace; runtime query must use same normalization. SQLite tokenizer is unicode61. Body metadata is NULL outside published subset.

IDs: p000001 etc, space0..space99, t0..t9, m0..m7. First half of source rows belong to space0; remaining spread over 99 spaces. Two tags per page, i%10 and (i+1)%10. Content is exactly 1 KiB, every hundredth 8 KiB; filler is intentionally repetitive and not company prose. Every fifth page includes 災難復原. All have disaster/recovery and a unique page token. Published subset has attachmentknowledge as a published-page marker in both body and PDF; this does NOT prove PDF-only extracted text indexing in this new builder. PDFs are complete synthetic one-page files with padding comments; sizes 4×64 KiB, 3×2 MiB, 1×8 MiB. No rendering/extraction claim; PDF-only search remains a separate integration requirement.

Formal 100k is **complete searchable rows plus a 256-page hot remote-content working set**, not 100k fully published page content. V2 adds one published page. Every supported read is a unique `{snapshotId,pageId,body}` JSON object, not a fake shared body. `manifest.bodyCoverage`, `bodyPageIds` and `nonPublishedBodyBehavior` explicitly describe the subset. Runtime must reject unpublished body with explicit BODY_NOT_PUBLISHED rather than fabricate content. The content workload should stay within the first 256 pages; source oracle includes the V2 added page for change checks.

Manifest db and objects descriptors: `{key,bytes,sha256,mimeType,file}`; file is relative to that version directory. DB key is `v1/search.sqlite` / `v2/search.sqlite`; body/media keys include snapshot and SHA. Publisher uploads descriptors and manifest after verification; DB is NOT duplicated in objects. DB and objects hashes are independent of reader responses.

Oracle root: `{schemaVersion,seed,sourceCount,sourceOracle,rankingContract,versions:{v1,v2}}`. Each version has `{count,queries,pages,media,changes}`. Query `{id,q,spaceId?,tags:[],identity:'all'|'a',total,eligibleIds:[]}`. Source predicates compute expected exact total and eligible IDs without querying SQLite. `a` means space0-only. Check exact total, unique results, min(10,total) rows, and each returned ID eligible. **This oracle does not assert BM25 ordering equivalence**; don't call it a full search-ranking quality evaluation.

Oracle `searchPages` includes every row's `{pageId,spaceId,title,tagIds,snippet}` for result metadata checks. `snippet` is the first 160 Unicode code points of original source content (`Array.from(content).slice(0,160).join('')`), computed without SQL; it is the exact expectation for the candidate's SQLite `substr(content,1,160)` prefix snippet, not query-aware highlighting. Runners must compare it exactly. Earlier generated oracles without this field must be retained as earlier attempts and not used for the strengthened contract; rebuild into a new directory and record builder hash. Oracle published page `{pageId,spaceId,tags,title,mediaId,bodySha,bodyBytes,bodyKey}`. Media oracle has mediaId plus descriptor; verify response bytes with oracle SHA, not response-provided hash. Page/body identity and snapshot must also match. Body SHA is of exact JSON.stringify(payload) plus newline; serving exact raw bytes preserves it. V2 moves p000001 to space1, changes p000002 tags to t8/t9, revises p000003 title/body, changes all PDF byte identities, adds p(COUNT+1). Unknown identities must not become allow. Latest-version mismatch behavior belongs to runtime contract.

Builder report separates elapsed wall time, process resourceUsage/maxRssKiB, DB bytes and published object bytes. It is not reader capacity or company human effort. Formal fixture generation must be recorded under the planned builder budget; pre-existing warmed files and generator cache need explicit disclosure.
