# DR 使用者旅程與驗收 Spec

版本：v0.2，2026-11-14，依第一輪JA-01–08修訂，供第二輪審查。狀態：供需求／架構審查的可談承諾，未獲公司PM、核心consumer、DevOps或授權owner接受。本輪只整理與挑戰既有證據，沒有新增功能測試。架構評審必須對照本文件的相同journey與profile，不因候選工具不同調低要求。

## 一頁閱讀：我們要讓誰完成什麼

事故中，廠區使用者需要找到能採取下一步行動的正確頁面、讀完必要內容、取得附件；一位核心consumer需要完成原本依賴搜尋API的工作；值班同仁需要知道哪些能力可用、哪些失敗與如何恢復。搜尋結果數量、少一個服務、HTTP200都不能代替這些工作完成。

| Journey | 代表故事（合成，待對口確認） | 完成的樣子 | 現況 |
|---|---|---|---|
| J01 進入可信的DR | 原站不可用，值班人員交給操作員DR入口 | 能進入、辨識唯讀、知道資料時間與可用功能 | 入口／登入／資料age UI未驗 |
| J02 找到需要的頁面 | 操作員只記得中文設備詞或錯誤碼，要找復原指引 | 在有權Space找到正確頁，知道為何相關 | 合成API有限證據；真任務品質與網頁體驗未驗 |
| J03 閱讀正文 | 搜尋結果顯示某SOP，使用者開啟含表格／長段落的頁面 | 正確同版正文完整可讀，4.5MB上限不靜默截斷 | 抽取與合成正文hash有限證據；正式Lexical渲染未驗 |
| J04 取得附件 | 使用者需下載清單交給現場同仁 | 正確授權檔案完整下載，失敗可理解與重試 | 小型合成bytes已驗；真檔案型態／大小未驗 |
| J05 核心consumer繼續工作 | 下游系統用查詢取得候選頁、正文與連結 | 一條代表流程可在DR完成，無須自行理解索引引擎 | 合成契約有證據；正式API與owner接受未知 |
| J06 更新中繼續操作 | 使用者搜尋後，系統恰好發布新版或換Web | 原操作鏈在允許窗口內繼續完成，內容不混版 | 目前跨reader409是差距，並未滿足透明續行 |
| J07 依賴暫時失聯 | 已在DR工作時物件來源暫停 | 依承諾profile維持必要工作，或清楚說明受影響能力 | 完整local小副本有限通過；remote JSON不能套用 |
| J08 多人使用與reader替換 | 廠區同時進入DR，某Web需重新建立 | 必要流量可用，重啟恢復不要求人工補資料 | 百萬合成短負載／冷副本已有子證據；整體未驗 |
| J09 授權改變 | 使用者失去Space權限或權限服務無法判斷 | 每次交付符合當時政策；拒絕不洩漏內容且可辨識 | mock allowset防護有證據；GM／撤權真整合未驗 |

## 需求狀態與協商規則

- **已知**：唯讀、搜尋、下載為已與PM確認的方向（依使用者描述）；所有Space合計百萬頁；搜尋只交付使用者有權Space的page；單頁Lexical JSON上限4.5MB，多數小很多；降低所有stakeholder總負擔，盡量沿用Next/MinIO/權限服務。
- **提案**：下列時間、負載、保留與附件範圍是準備者給出的具體討論起點；不是正式SLO/RTO/RPO。可以談，但調整需記錄對旅程、受益者、受損者與證據的影響。
- **不變底線**：不能未授權交付；不能靜默混版／截斷必要內容／以空結果假裝服務正常；資料是否適用、哪些能力不可用需可辨識。不能靠拒絕所有請求聲稱可用。
- **證據狀態**：已知要求、提案要求、有限驗證、尚未驗證、原型不符合、暫不支援分開使用。只有對口接受＋同範圍驗收完成才可寫正式滿足。
- **成本歸屬**：Spec描述使用者結果，不要求consumer吞下版本協調。維運與開發成本仍須架構review逐項攤開；需求鬆綁要由受影響對口接受，不能只因某實作較容易。

## 兩個可討論的服務承諾

**P-C 核心延續提案**：原站／原backend不可用，但DR入口、DR物件來源與授權依賴可用。J01–J06/J08/J09必要工作仍可完成。資料不因工具選擇縮成只有少量Space。這是正向成功的依賴前提；依賴失聯後，J07/J09的錯誤、能力狀態、保留操作上下文與重試契約仍是P-C必要需求，不能標成「P-C外」而不處理。正確503可通過故障訊號測試，但該必要工作沒有完成，仍計可用性缺口。

**P-I 物件來源中斷延續提案**：在P-C之外，對已啟動reader與事先列出的必要任務清單，DR物件來源中斷15分鐘仍可搜尋、閱讀、下載。清單必須列page/附件與版本，不能只寫「有cache的就可以」。P-I在承諾起點須有至少15分鐘的可信資料有效期餘額及完整必要物件；沒有餘額不得宣稱P-I ready，仍須提供P-C降級訊號並記P-I工作不可用。未完成資料準備的新reader不冒充ready；增加獨立Web故障與新reader冷啟動是另一個更強故障組合，未自動含入P-I。正式授權仍須成立，P-I不授權在GM unknown時沿用不明權限。

二者是可談的使用者保證，不是指定local或remote架構。接受P-I會要求架構證明對指定內容不再依賴故障中的來源，並付出對應成本。

Q3/Q4先固定小型常態與最大附件點，不宣稱代表公司完整分布。Q2最大Lexical頁仍需保留完整原文，即使搜尋preview/highlight另有明示降級。提出附件上限不改變已知page上限，也不把所有百萬頁都假定為4.5MB。

## v0.2：操作時鐘、工作分母與政策優先序

### 操作時鐘（JA-01）

| 操作 | 計時起點→終點 | 提案目標／期限 | 失敗如何記 |
|---|---|---|---|
| search API | 預定到達／使用者送出→完整回應bytes可驗證；含排隊、授權、網路 | P95≤2s，單次deadline5s | deadline、漏送、錯結果均失敗；不只量engine時間 |
| body API | 直接閱讀的預定到達，或上一步search完成→完整正確正文bytes | P95≤2s，單次deadline5s | 同上；排隊不重置時鐘 |
| 網站搜尋／正文 | 使用者操作→必要結果可辨識／正文可讀 | 結果P95≤3s；最大頁正文P95≤5s | API成功但畫面不可用仍是旅程失敗；不是用API timing替代 |
| attachment first byte | download任務預定可開始→首個有效檔案byte | ≤2s；在Q4網路及已建立連線條件下 | 錯誤頁／空body不當首byte成功 |
| attachment complete | 同一download起點→完整正確bytes | ≤10s，適用≤20MiB；**不套search5s** | 中斷、部分檔、重試後仍超總期限均失敗，不重新起時計帳 |
| 合成正向三步鏈 | 該鏈預定到達→同版search/body/media全部正確完成 | deadline20s，且每操作各自期限也須符合 | 任一步失敗、未送後續步或權限/內容錯誤即鏈失敗 |

Q4的100Mbps/RTT50ms只定義附件研究網路，不自動代表公司網路或Q8冷下載頻寬。若要拿100Mbps評reader恢復，需明確追加同一條件再計算／實測，不能靜默混用。

### 固定到達、有限併發與成功分母（JA-03）

Q3採open-loop邏輯任務排程：每秒固定兩條正向search→body→attachment鏈（相隔500ms），另四個直接body任務；30min共3600條鏈、7200個直接body任務。每條鏈的body/media依前一步完成才可發出；完整時總義務為3600 search、10800 body、3600 media。10表示同時在途HTTP slot，不代表慢下來就減少新任務；10個合成身份按固定oracle輪替。

待處理上限100；超出、漏送、排隊超過各操作期限都記失敗，不能丟棄後只報成功樣本。前步失敗而未發出的後續操作標dependency-blocked，仍是未履行的操作義務，不能因它沒有HTTP就消失。每筆記scheduledAt、eligibleAt、dispatchAt、completedAt、queue time與錯因；鏈的20s從預定到達起，不因排隊延後。

成功率分開：3600條正向完整鏈≥99%；search/body/media各類預定操作義務各≥99%；10個代表必要任務**每一項**都須能完成，不能用其他簡單任務稀釋完全不支援的一類。錯內容、越權與混版零容忍。專門的未知授權/越權/錯版/缺件等預期拒絕測試另列分母；405次符合預期含拒絕，不是405次工作成功。只有實際發送的延遲分布會另列，漏送/blocked不能因此從成功率分母移除。

### 開鏈、資料age、保留與撤權（JA-02／JA-05）

優先序為 **可信當前授權與安全政策 → 資料有效期 → 已簽發鏈窗口 → 物件保留**。保留檔案或延長租約不增加交付權限，也不延長資料有效期。

提案預設保留完整15min鏈，而非暗中縮短：開新鏈時，須證明sourceCut+24h（保守扣除已知時鐘誤差）至少還有15min，且該版本的必要物件可保留至鏈到期；回傳issuedAt/expiresAt與資料時間。版本已23h59m時不回一組聲稱可操作15min的hits/URLs；回系統級DATA_EXPIRING、保留查詢/篩選上下文、提示等待新版本或重新整理。這會在最後15min提早停止新鏈，是本提案的明確可用性代價，需PM/consumer/資料owner接受。已開且仍符合授權/age政策的鏈不能因新版發布或換Web而409；若政策撤銷或版本被判不可信，停止交付並回可理解原因。

如果無法證明sourceCut或時鐘誤差上界，不得偽裝age有效；顯示資料時間無法確認並記必要工作不可用。P-I宣告15min中斷延續時也要同樣餘額與完整必要集合；若只有10min餘額，不能標P-I成功。另一可談選項是明示縮短窗口或受控過期使用，但都需新profile/owner接受，v0.2沒有默認開啟。

Q7的T_eff是權威政策的提交／生效事件；t_auth是本次請求取得權威當前decision及資源歸屬的一致判斷點；T_seen是DR觀察事件的時間，只供診斷，不能把撤權承諾偷偷從T_seen才開始算。預設每個請求在t_auth需證明使用同一當前policy epoch：若撤權在t_auth前生效，此操作不能取得allow。TTL0僅表示不跨請求沿用allow，不能證GM內部沒有陳舊資料；GM是否能給可信current decision/epoch/asOf/current binding契約仍是工程未知。資訊缺失、過期或epoch不相容時回授權不可判斷，並記可用性缺口。

**current resource binding是預設政策**：page由S1移至S2，即使讀舊內容版，仍按當前資源歸屬判斷；不能只把當前allowset套到舊page.spaceId。search的候選、total、rank、snippet、分頁也要受當前membership約束，不能只在回傳hit後補過濾。沒有可信且相容的mapping時可拒絕受影響查詢，但這不是搜尋成功。body/media同樣按當前binding；正文中備份時的來源metadata若仍顯示，需與當前存取範圍區分，不能拿它作授權依據。

本提案的串流界線是**每操作admission**：在T_eff之前已取得有效allow而開始的下載，單次grant最多涵蓋Q4的10s完成窗口；已交付bytes不能回收，且不宣稱中途即時撤銷。撤權後的新請求不得重用舊allow。要求串流期間每個chunk可即時撤回是更強且尚未接受／驗證的政策，需要取消傳播、有效期與可觀察截止點另立profile；不能由TTL0或每次HTTP檢查推論已做到。這項in-flight風險與最大窗口須授權owner確認，不隱藏於「每次都驗權限」一句話。

### 不洩漏存在性的錯誤與恢復語意（JA-04／JA-06）

| 狀態 | 一般使用者／consumer外顯提案 | 禁止的解讀 |
|---|---|---|
| 可信授權範圍搜尋，結果為零 | 正常成功，表示「目前可見範圍沒有符合結果」 | 不列未授權Space或聲稱某隱藏頁存在 |
| 可信判斷下，物件不存在或無權讀 | 共用404/RESOURCE_NOT_AVAILABLE及相同外顯欄位/文案 | 不用403/404或不同內容透露特定page是否存在 |
| 系統層身份／授權狀態不可判斷 | 503/AUTH_UNAVAILABLE，提示稍後重試或取得協助 | 不改成空集合假成功；不得依先查到物件存在與否改出不同外顯訊號 |
| 物件來源逾時／不可達，或承諾版本缺件 | 503/CONTENT_UNAVAILABLE；分開顯示搜尋/閱讀/下載能力並保留已授權操作上下文 | 不是零結果、成功空檔或「這頁沒有權限」 |
| 可信上下文的資料age／鏈期限不足 | DATA_EXPIRING／DATA_EXPIRED或CHAIN_EXPIRED，提供重新整理/重搜步驟 | 不把版本期限當資料仍可交付的權利；不讓任意pageId探測期限訊號洩漏物件存在 |

對一般使用者隱藏物件存在性的語意須UI/API一致；受信任維運診斷可記實際原因，但不能直接顯示給請求者。錯誤碼名稱為可談契約提案，還不是正式既有API。

P-C的正向承諾依賴來源可用；失聯時以上降級、錯誤、保留查詢與重新可用後重試仍是必要要求。受控失敗測試應驗503及上下文，再驗來源恢復後可沿仍有效鏈重試；若鏈已過期，回明確重搜流程。這不把失敗的工作計成成功，也不要求consumer自行選擇另一引擎或拼接不同版本。P-I則另外要求指定必要工作在來源失聯期間仍完成。

## 詳細旅程卡

### J01：原站失效後進入可判斷的DR（V3/V5/V7）

**觸發與路徑。** 操作員接到原站不可用通知，從經確認的入口進入，完成登入，看見唯讀狀態、資料來源時間、目前可用功能，再開始找復原文件。若入口、身份或資料尚不可用，畫面指出受影響能力與下一步，不顯示假成功。

**驗收。** P-C下指定使用者可走完入口→身份→J02工作；Q8整體時間線要含路由/登入。Q6資料age資訊可讀，不能只有程序綠燈。

**證據與差距。** [MR1](../../../docs/reviews/minio-release-2026-11-14/final-review.md)及[MR2](../../../docs/reviews/minio-dependency-2026-11-14/final-review.md)僅有loopback Next/API、ready與reader替換；沒有使用者入口、DNS、登入與age介面。不是尚未選工具造成的缺口。

**協商。** 入口方式與啟用通知可改；不可以localhost或process ready取代使用者可到達。要求無人工啟用或更短15min目標時，須增加導流／身份／值班流程證據。

### J02：從不完整記憶找到需要的頁面（V1/V4/V6）

**觸發與路徑。** 使用者輸入中文設備詞、英文症狀或錯誤碼，先看到有權Space的相關頁；從標題/片段判斷候選、修正一次查詢或翻頁，選擇正確文件。已授權搜尋零結果與系統授權不可判斷可辨識；單一物件不存在/無權則共用外顯語意，不能為好懂而洩漏隱藏內容存在。

**驗收。** Q1必要任務及Q2/Q3時間/負載；當前可信資源歸屬與權限在total、snippet、排名與分頁前生效；舊索引metadata不自動等於當前membership。搜尋語意提案先承諾基本多詞AND；排序可不同於原站，但不能因此找不到必要頁。拼字容錯、同義詞、聚合與任意DSL未含基本級，若任務依賴即升為必要。

**證據與差距。** [ES容量](../../../docs/reviews/s1-capacity-2026-11-14/final-review.md)、[SQLite scope策略](../../../docs/reviews/s1-scope-2026-11-14/final-review.md)同合成工作集百萬短窗口通過；原混合P95約111ms/2436ms，混合分布不能直接當純搜尋P95；[既有HTTP事後分段](../../../evidence/journey-architecture-2026-11-14/coordinator/posthoc-http-slices.json)將64個search與16個body分開，search P95約115ms/2446ms，SQLite有8/64次search超2s。這是既有原始資料的唯讀分析，非新測試或正式SLO；兩者都沒有真任務品質、Q3長時負載或瀏覽器3s證據。ES是參照，不是正確性oracle。

**協商。** 可談AND/模糊與preview降級，需以任務能完成為依據；若必要結果只在目前第1000筆外，不能用原型窗口上限直接判使用者不合理，須改查詢/導航或能力範圍。

### J03：閱讀正確且完整的頁面（V1/V5）

**觸發與路徑。** 操作員開啟找到的SOP，閱讀文字、連結與結構資訊；即使頁面接近4.5MB，也不因搜尋抽取限制失去必要段落。缺件或版不符時保留上下文並顯示可採取行動。

**驗收。** 頁面ID/版本與搜尋鏈一致，必要Lexical節點可呈現；最大page按Q2可讀。原文完整性與搜尋抽取/preview上限分開驗；未知節點不得靜默丟內容。

**證據與差距。** [S1小型Lexical](../../../docs/reviews/s1-es-2026-11-14/final-review.md)有1107抽取核對與4.5MB附近合成案例；MR1/MR2有合成正文bytes/hash。沒有公司完整Lexical renderer、內嵌內容與遠端MinIO JSON旅程證據。

**協商。** 可談先呈現文字再載入非必要裝飾；不可靜默刪掉必要表格或長頁末段。若要求還原所有原站互動/嵌入，屬新工作範圍，需新增節點相容與安全呈現證據。

### J04：取得能實際使用的附件（V1/V4/V5/V6）

**觸發與路徑。** 使用者從頁面取得檢查清單，確認檔名/大小後下載；失敗後知道可重試或聯絡誰，不拿到錯版或部分檔冒充成功。

**驗收。** 正確授權、同版、完整bytes；Q4首byte/總時間。對外提供必要檔名、內容型態與失敗訊號；若中斷需明確顯示未完成。

**證據與差距。** MR1小型三個88-byte附件、MR2唯一68-byte百萬引用附件的HTTP與SHA通過；不是20MiB、真格式、瀏覽器儲存或Range證據。

**協商。** 大小、格式與續傳可分級；若真任務需要超20MiB，就新增範圍及資源測試，不可因原型小檔通過宣稱下載已完整驗收。

### J05：核心consumer在DR完成原有工作（V2/V4/V7）

**觸發與路徑。** 一個核心下游系統查詢頁面、選取候選、讀正文並取得必要附件／連結；遇到無結果、拒絕或暫不可用，走明確的可重試/終止路徑。

**驗收。** 提出相容外層契約：query/Space範圍/分頁，回pageId、title、片段或明示不可用原因、可直接跟隨URL，以及穩定機器錯誤；consumer不需要知道ES/SQLite/版本路由細節。正式字段名稱與既有API比對後才定版；一條owner提供的代表流程須可重播，記錄改碼/設定/錯誤處理成本。

**證據與差距。** S1與MR1/MR2合成HTTP流程有證據，沒有正式API樣本或owner接受。JSON近似不代表相容；原型409與結果上限亦未被接受。

**協商。** 排序差異、無highlight與分頁窗口可談，但不能自行移除被工作流依賴的字段。要求原ES DSL完全相容、全量遍歷或零client改碼會觸發契約與adapter重審。

### J06：切版與Web替換不打斷既有旅程（V2/V5）

**觸發與路徑。** 使用者搜尋後離開兩分鐘，再開正文與附件；此時已有新備份或請求被送到另一Web。使用者應沿原搜尋鏈取得同版資料，無需理解release。

**驗收。** 通過Q5開鏈條件後的15min窗口內，body/media/後續分頁在授權及資料政策仍有效時跨程序成功；不能只因換Web/發布新版而409。若撤權或資料被判不可信，安全/age優先，按v0.2政策終止而非偷偷換新版。窗口外可提示「此搜尋已過期，重新搜尋」，但需保留查詢上下文。

**證據與差距。** MR1/MR2證明原程序固定舊版、新程序拒舊URL409，防混版成立但本旅程不符合；沒有透明版本路由、舊版保留期限或跨reader分頁證據。ES baseline亦未證明這個跨內容/附件契約。

**協商。** 15min可縮短/延長；允許重新搜尋是另個較低承諾的profile，須由PM/consumer接受並保留失敗成本，不當作現提案已滿足。延長至天或要求永久連結，觸發保留/路由/授權/GC重審。

### J07：依賴失聯時知道仍能完成什麼（V3/V7）

**觸發與路徑。** DR使用中，物件來源暫時失聯。P-C可顯示閱讀/下載暫不可用與重試下一步，不能以零結果或成功空檔取代；P-I指定任務仍要完成。

**驗收。** 明確區分search/body/media能力；P-I對列明任務在15min內維持J02–J04，不能只報健康或任意cache hit；授權仍按J09。新的空reader不可假ready。

**證據與差距。** MR2真MinIO失聯10.037秒、24頁完整local副本有限鏈成功；沒有15min、公司remote JSON、同時Web損失、GM失聯與百萬舊reader併發證據。

**協商。** P-I是否必要、任務集合與15min長度可談；若改成所有資料、所有新reader或多依賴同失效，應視為故障範圍變更，不能只調timeout。

### J08：尖峰與恢復時仍有可用服務（V3/V4/V8）

**觸發與路徑。** 原站故障後多人進入DR；一個reader替換時其他使用者繼續閱讀。值班人員依runbook恢復reader，不手工補fixture、改索引或修改保護條件。

**驗收。** Q2/Q3固定到達負載下，完整正向鏈及各操作義務成功率分別≥99%，每項代表必要任務皆可完成；非預期錯誤/漏送/blocked/timeout計入，預期拒絕另列；安全或內容錯誤零容忍。Q8 reader子目標與事故整體目標分開，量最長中斷及人工步驟；非作者操作一次。

**證據與差距。** MR1兩次空cache約12.67/13.08秒至必要鏈、MR2節流更新至大版任務105.95秒，只是同host/warm OS/受控程序；沒有正式Pod/主機隔離、10 client30min、百萬舊版更新或非作者接手證據。2.133GB含正文/FTS，不是純索引或真Lexical分布。

**協商。** 可談活動client、到達率、資料長尾與恢復時間，不改百萬總量/4.5MB已知上限。要求沒有任何本地磁碟、同時多reader冷恢復或更大附件，需重估資料交付及資源。

### J09：權限改變時仍值得信任（V6/V7）

**觸發與路徑。** 使用者剛搜尋某Space後被撤權，或授權服務只知道部分Space。下一次閱讀/附件應依可信可判斷範圍交付；unknown部分不變成allow，也不洩漏被拒內容的存在與片段。

**驗收。** Q7跨請求不沿用allow；在權威當前policy epoch判search總數/排名/片段、正文、附件及current resource binding，T_eff/t_auth/T_seen與in-flight例外依v0.2明定，不能只靠DR已收到事件或舊page.spaceId。授權不可判斷時用明確服務錯誤，與無結果/無權限分開；此時必要工作不可完成須計為可用缺口。

**證據與差距。** S1獨立SQL反例與MR1/MR2 mock身份有授權集合/unknown拒絕證據；沒有GM真憑證、撤權事件、權限一致性時延或資料跨Space移動政策證據。

**協商。** 部分可判斷Space服務可先提供，但需證明不洩漏unknown；授權快取TTL、離線授權與fail-open不可只由技術團隊取捨。若owner接受有界離線授權，需另版政策與撤權風險測試，不把資料版本pin當授權。
